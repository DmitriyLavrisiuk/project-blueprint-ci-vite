# Документация

Каждый документ открывается шапкой: на что отвечает, что сюда не писать, где источник правды. Начни с шапки; если документ относится к задаче — читай целиком.

| Документ                     | Когда читать                                                                              |
| ---------------------------- | ----------------------------------------------------------------------------------------- |
| [STATUS.md](STATUS.md)       | начало любой сессии — что работает и что в работе                                         |
| [ROADMAP.md](ROADMAP.md)     | планирование — версия в работе, её задачи и проверки                                      |
| [WORKFLOW.md](WORKFLOW.md)   | как работаем: решения владельца, цикл задачи, версии и выпуск, рабочая папка .tmp, аудиты |
| [DEPLOYMENT.md](DEPLOYMENT.md) | выкатка на GitHub Pages: проверки, откат |
| [ui/README.md](ui/README.md) | перед любым UI-кодом — правила, дизайн-система, компоненты и страницы                     |

## Правила ведения

1. **Один факт — один дом.** Правило или факт описан в одном документе — в том, чья шапка за него отвечает; остальные ссылаются, а не пересказывают. Исключение одно: `.claude/CLAUDE.md` даёт инвариант одной фразой со ссылкой на его дом.
2. **В документе — только действующее.** Что было раньше и почему поменяли — в `CHANGELOG.md` и git.
3. **Изменчивые числа — только в [STATUS.md](STATUS.md)**: число тестов, версии окружения, адреса проверки.
4. **Правило — коротким пунктом, а не абзацем**: строка не длиннее 600 знаков. Происхождение — одна дата в скобках.
5. **Шапка из четырёх строк** у каждого документа: на что отвечает, что сюда не писать, где источник правды, когда обновлять.
6. **Имена:** документ — `UPPER-KEBAB-CASE.md`, папка — `lower-kebab`; в каждой папке `README.md` со ссылкой на каждый её документ и на `README.md` подпапок.
7. **Ссылки** — относительные Markdown-ссылки, раздел — якорем; документ в тексте называется ссылкой или путём в обратных кавычках. В заголовках нет дат, кода и эмодзи — иначе меняется якорь.
8. **Куда писать:** порядок работы — [WORKFLOW.md](WORKFLOW.md), план — [ROADMAP.md](ROADMAP.md), состояние — [STATUS.md](STATUS.md), история — `CHANGELOG.md`.
9. **Запись в CHANGELOG — 2–3 строки, не длиннее 600 знаков,** со ссылкой на раздел docs; подробности — в docs и в сообщении коммита.
10. **Отчётов аудитов в docs нет** — порядок разбора в [WORKFLOW.md, «Аудиты»](WORKFLOW.md#аудиты). Удалённые отчёты достаются из git.
11. **Стандарты кода — не в docs, а в `.claude/rules/`**: файл на тип файлов, в шапке — `paths:`, поэтому правило подгружается само, когда агент читает или правит такой файл. Без `paths` правило грузилось бы в каждую сессию. Что проверяет линтер, держит его конфиг; в правиле — как писать код.

## Проверка

`node scripts/check-docs.mjs` держит правила, которые проверяет машина:
- упомянутые в обратных кавычках файлы и команды `npm run`, `composer` существуют, пути — с учётом регистра; пути `docs/…` в агентах и правилах ведут на документы;
- ссылки и якоря ведут на существующее;
- шапка из четырёх строк, имена по правилу 6, каждый документ есть в `README.md` своей папки, документ в тексте назван ссылкой или путём;
- в заголовках нет дат, кода и эмодзи;
- одна фраза от 60 знаков не стоит в двух файлах — docs, `.claude/CLAUDE.md`, агентах и правилах: у факта один дом по правилу 1, в остальных — ссылка;
- STATUS не длиннее 50 строк, строки документов не длиннее 600 знаков, запись в `[Unreleased]` CHANGELOG — тоже;
- разделы ROADMAP — версии, «Дальше» и «Без версии», подзаголовки без номеров;
- номер версии совпадает в манифестах, CHANGELOG и последнем теге; тег может отставать, пока выпуск ждёт тега;
- вне кода нет незаполненных плейсхолдеров шаблонов.

Проектное — какие папки считать кодом, какие имена искать в коде, где ещё лежит номер версии, какие строки обязаны повторяться (`allowRepeats`) — задаёт `.docs-check.json` в корне.
