# Как мы работаем

## Решения владельца

- Если вариантов несколько — показываем их, рекомендуемый первым; решает владелец, работа идёт после его ответа.
- Первым предлагаем самое простое правило, без условных веток; условие — только как возможность, не по умолчанию.
- Задачи из раздела «Когда сомневаешься» в `.claude/CLAUDE.md` — сначала план и подтверждение владельца.

## Цикл задачи

- Задача → проверяемая цель → код, тесты и документация → линтеры и тесты (команды — в `.claude/CLAUDE.md`) → коммит. Коммит, тег, выкатка и пуш — только по команде владельца.
- Работаем в main; ветку заводим по решению владельца. Сообщения коммитов — Conventional Commits (`feat:`, `fix:`, `docs:`, `chore:`).
- После значимой задачи: `STATUS.md` перезаписью (до 50 строк), строка в `CHANGELOG.md` в `[Unreleased]`, отметка в `ROADMAP.md`; правила документации — [README.md](README.md).
- Проверки перед коммитом — `.githooks/pre-commit`: проверка docs, секреты, линтеры стека. В свежем клоне их включает `git config core.hooksPath .githooks`; обходить их `--no-verify` нельзя без слова владельца.

## Версии

1. **Только SemVer.** У проекта одна версия во всех манифестах; других номеров у плана нет.
2. **Шаг плана — минорная версия:** раздел ROADMAP `## vX.Y — цель`, задачи с «→ проверка». Нумерованных подэтапов нет, внутри — подзаголовки без номеров. Если выкатка идёт по одной задаче, шаг просто маленький.
3. **Номер получает версия, за которую берёмся;** дальше — цели по порядку без номеров, до v1.0 с definition of done. Кроме версий, у ROADMAP два постоянных раздела: «Дальше» — эти цели, и «Без версии» — задачи вне версий, в том числе остатки аудитов. Выпущенный номер вечен, запланированный может отпасть, поэтому дыр в номерах нет.
4. **Выпуск — после проверки** — раздел «Выпуск версии».
5. **Между шагами — патчи:** исправления без новых возможностей, в ROADMAP их не планируют. 0.x — до запуска, 1.0.0 — запуск; дальше MINOR — новые возможности, MAJOR — несовместимое: адреса, схема данных, публичное API. Подсказка — коммиты: `feat` — minor, `fix` — patch.
6. **«Не ждёт релиза» значит «не в этой версии»:** незаконченное уходит в следующую, готовое выходит с текущей.

## Выпуск версии

1. Задачи версии в ROADMAP закрыты; линтеры, сборка и тесты без ошибок; каждая «→ проверка» пройдена.
2. Агент release-qa по `<последний тег>..HEAD` отвечает «готово к выпуску».
3. `node scripts/bump-version.mjs X.Y.Z` (или `minor`, `patch`) ставит номер во все файлы, где он лежит, а `[Unreleased]` в CHANGELOG превращает в `[X.Y.Z] — дата`. Раздел версии в ROADMAP убирается, незаконченное уходит в следующую.
4. Коммит и тег `vX.Y.Z` — по команде владельца; пуш вместе с тегами.

## Рабочая папка .tmp

- Временные файлы работы — только в `.tmp/` в корне репозитория; она в `.gitignore`.
- В корне `.tmp/` файлов нет — только папки по назначению:

| Папка      | Что лежит                                      | Когда убирается                                         |
| ---------- | ---------------------------------------------- | ------------------------------------------------------- |
| `scripts/` | разовые скрипты: выборки, правка данных, пробы | после прогона; нужный повторно переезжает в репозиторий |
| `checks/`  | проверки в браузере: скрипты и скриншоты       | в конце задачи                                          |
| `audits/`  | отчёты аудитов до разбора находок              | когда каждая находка разобрана — раздел «Аудиты»        |
- Ничто в `.tmp/` не источник правды, и docs на эти файлы не ссылаются.
- Убирает тот, кто создал, — в конце своей задачи.

## Аудиты

- Отчёт аудита — рабочий файл в `.tmp/audits/`, в документацию не попадает.
- Каждая находка исправляется, становится задачей ROADMAP — в версии или в «Без версии» — или правилом в своём документе. После разбора отчёт удаляется, в `CHANGELOG.md` — строка с итогом.

## Приём идей

- Идея — строкой в «Дальше» или «Без версии» ROADMAP; в версию она попадает по выбору владельца, с проверкой у каждой задачи.
